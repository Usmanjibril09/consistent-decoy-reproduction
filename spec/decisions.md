D30 2026-11-04 Stage-2 completion amendments, before full training and before Phase 3.
(a) Correct literature attribution: NeuralPot's available accepted manuscript compares separate GAN and AE models
    (https://gala.gre.ac.uk/id/eprint/27976/); it does not establish a latent GAN/AE cascade. B6 implements the D29
    requested cascade and is labelled a GAN+AE adaptation, not a reproduction. Encoder/decoder are dense networks
    over flattened command+response horizons; a latent GAN follows the training-only AE phase. Exogenous tags are replayed.
(b) B4 jointly autoregresses command+response values, seeded only by warm-up, with per-channel Gaussian residual noise
    fitted on training one-step residuals after selecting weights. Its early-stopping loss is free-run response MSE;
    hyperparameter selection remains K-dev. B5 is a command/exogenous-conditioned LSTM GAN with warm-up encoder,
    one discriminator and one generator update per iteration, BCE losses. These are declared task adaptations.
(c) B7 uses GRU embedder/recovery/generator/discriminator and an L-1-layer supervisor, training-only min-max scaling,
    three phases, gamma=1, generator supervised/moment weights=100, reconstruction weight=10, joint supervised
    embedder weight=.1, two G/E updates per D update and D threshold .15, following the authors' implementation.
    Adaptations: command+response channels only (exogenous replay), horizons 300/500, configured learning rates,
    small sqrt numerical floor, same minibatch within each joint iteration. Original reference:
    https://github.com/jsyoon0823/TimeGAN/blob/master/timegan.py . No claim of bitwise TensorFlow reproduction.
(d) K-dev uses a fixed 32-channel two-convolution CNN, fixed seed 1729, balanced paired real/generated examples,
    a contiguous 80/20 validation-window split, and PURGES overlapping full windows at that boundary.
    Classifier normalization is fitted on its training partition only. This corrects the literal D29 split's leakage
    risk. K-dev is distinct from all held-out attackers. Ties in selection choose the first configuration.
(e) C3 precedes C2 so fallback cannot bypass the consistency layer. Non-valve clipping remains true as approved.
    C2 symmetric rate/range audit uses unique adjacent training rows, with no cross-recording transitions; threshold
    is <5% changes for each tag. The audit does not assert that the full dynamic rules preserve all real trajectories.
    Motor current's algebraic relation takes precedence over generic current range/rate clipping. Coverage uses
    a 1e-6-of-training-range numerical tolerance to avoid float32 round-trip false activation on training values.
    A3 removes future command conditioning; its warm-up still contains observed command history, as in stage 1.
(f) Evaluation batch=32. Cache and resume guard binds source/config/package versions, ordered dimensions and training/
    validation data. Checkpoints retain optimizer and RNG states; exact CPU GAN resume is tested across all phases.
    Training-only export uses a content manifest instead of claiming an uncommitted snapshot is a clean git commit.
    No full training or Phase 3 test results are used to choose these changes. GPU smoke is required before Kaggle full run.
(g) Kaggle capacity preflight tests the largest grid models at effective batch 256 on the selected GPU, using B8's
    prescribed microbatch accumulation. Its discarded weights are not candidates. A configurable wall-time budget
    pauses only after a checkpoint; full budget/seed counts are not shortened to promise overnight completion.
(h) Execution order prioritizes C1/A3 and their inference layers, then the baseline comparisons. This changes no
    configurations, selection rules, training iterations or seeds; interrupted sessions resume the remaining work.
